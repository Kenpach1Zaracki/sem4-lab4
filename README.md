# SafeTrack — Система мониторинга и расследования инцидентов ИБ

Веб-приложение для учёта, анализа и корреляции инцидентов информационной безопасности на промышленном предприятии. Проект выполнен в рамках РГР по теме: **«Разработка защищённой системы мониторинга инцидентов информационной безопасности с элементами анализа рисков»**.

## Назначение системы

SafeTrack помогает сотрудникам службы безопасности фиксировать инциденты, автоматически рассчитывать риск каждого события, находить группы связанных инцидентов, вести журнал расследований и формировать аналитические отчёты. Приложение включает Express backend, React frontend, PostgreSQL, JWT-аутентификацию с двухфакторкой, RBAC, Swagger и аудит-логирование.

## Связь с темой РГР

РГР требует не только CRUD для инцидентов, но и модель анализа, средства защиты информации и разграничение доступа. В проект добавлены:

- **Risk Calculator** — автоматический расчёт `risk_score` (0–100) и `risk_level` (low/medium/high/critical)
- **Текстовое объяснение** `detection_reason` для каждого инцидента
- **Корреляция инцидентов** — группировка в `correlation_alerts` по типу и локации
- **Дашборд** с аналитикой, круговой диаграммой и таймлайном
- **Импорт/экспорт** инцидентов через CSV
- **Двухфакторная аутентификация** через EmailJS
- **Аудит-логирование** в БД + файл `audit.log`
- **Rate limiting** на попытки входа
- **Валидация** входных данных на бэкенде
- **Защита от XSS** (санитизация комментариев, Helmet)
- **Хеширование IP** в логах

## Модель анализа инцидентов (Risk Calculator)

При создании или изменении инцидента backend автоматически пересчитывает:

- `risk_score`: число от 0 до 100
- `risk_level`: `low`, `medium`, `high`, `critical`
- `is_suspicious`: `true`, если `risk_score >= 50`
- `detection_reason`: русскоязычное объяснение
- `analyzed_at`: время анализа

### Веса признаков для расчёта риска

| Признак | Вес |
|---|---|
| severity = Низкий | +10 |
| severity = Средний | +25 |
| severity = Высокий | +50 |
| severity = Критический | +70 |
| Тип: Утечка данных | +40 |
| Тип: Несанкционированный доступ | +45 |
| Тип: Вредоносное ПО | +35 |
| Тип: Физическое проникновение | +40 |
| Тип: Отказ оборудования | +30 |
| Тип: Нарушение ТБ | +20 |
| Тип: Ошибка персонала | +10 |
| Локация: Серверная | +15 |
| Локация: Склад ГСМ | +15 |
| Локация: Лаборатория | +10 |

### Уровни риска

- `0–24`: low (Низкий)
- `25–49`: medium (Средний)
- `50–74`: high (Высокий)
- `75–100`: critical (Критический)

## Правила корреляции

Корреляция запускается автоматически при создании/обновлении инцидента. Группировка происходит по совпадению **типа** и **локации** за последний час.

| Условие | Alert |
|---|---|
| 2+ инцидента одного типа в одной локации за час | «Группа: [тип] ([локация])», риск = макс. риск в группе |

## Роли пользователей

| Роль | Права |
|---|---|
| **admin** | Полный доступ: CRUD, админ-панель, управление пользователями, журнал логов, дашборд, алерты, импорт/экспорт |
| **investigator** | Создание инцидентов, редактирование назначенных, комментарии, дашборд, алерты, импорт CSV |
| **user** | Просмотр только своих инцидентов, без права создания и редактирования |

## Средства защиты информации

| Механизм | Реализация |
|---|---|
| Аутентификация | JWT-токены (24h) + двухфакторка через EmailJS |
| Хеширование паролей | bcryptjs, 10 раундов |
| Разграничение доступа | RBAC: 3 роли, middleware `requireRole`, `requireAdmin` |
| Защита API | Проверка JWT на каждый запрос, закрытые эндпоинты |
| Rate limiting | 5 попыток входа в минуту |
| XSS-защита | Helmet, санитизация комментариев |
| SQL-injection защита | Параметризованные запросы (pg) |
| Аудит-логирование | БД (таблица `logs`) + файл `audit.log` |
| Хеширование IP | SHA-256 (первые 12 символов) в логах |
| Валидация | Проверка обязательных полей на бэкенде |
| Обработка ошибок | Без раскрытия внутренней информации (401/403/500) |
| CORS | Настроен для доверенных origin |

## API endpoints

### Аутентификация

- `POST /api/auth/register` — регистрация
- `POST /api/auth/login` — вход (шаг 1, возвращает код 2FA)
- `POST /api/auth/verify-2fa` — подтверждение 2FA (шаг 2, возвращает JWT)
- `GET /api/auth/refresh` — обновление токена

### Инциденты

- `GET /api/incidents` — список (с фильтрацией по роли)
- `POST /api/incidents` — создание + авто-расчёт риска (admin, investigator)
- `PUT /api/incidents/:id` — обновление + пересчёт риска
- `DELETE /api/incidents/:id` — удаление (admin)

### Комментарии

- `GET /api/incidents/:id/comments` — список комментариев
- `POST /api/incidents/:id/comments` — добавить комментарий (admin, investigator)

### Аналитика

- `GET /api/analytics/summary` — сводка для дашборда
- `GET /api/analytics/risk-distribution` — распределение рисков
- `GET /api/analytics/timeline` — активность за 24 часа

### Корреляция

- `GET /api/correlation/alerts` — список алертов
- `PUT /api/correlation/alerts/:id` — изменить статус
- `DELETE /api/correlation/alerts/:id` — удалить алерт (admin)

### Dataset (импорт/экспорт)

- `POST /api/dataset/import` — импорт CSV (admin, investigator)
- `GET /api/dataset/export` — экспорт в CSV
- `GET /api/dataset/sample` — скачать пример CSV

### Администрирование

- `GET /api/admin/users` — список пользователей (admin)
- `PUT /api/admin/users/:id/role` — сменить роль (admin)
- `DELETE /api/admin/users/:id` — удалить пользователя (admin)
- `GET /api/admin/logs` — журнал аудита (admin)
- `GET /api/admin/audit-log/download` — скачать audit.log (admin)

**Swagger-документация:** `/api-docs`

## Структура базы данных

| Таблица | Назначение |
|---|---|
| `users` | Пользователи (id, name, email, password, role) |
| `incidents` | Инциденты + поля risk_score, risk_level, detection_reason, is_suspicious |
| `roles` | Справочник ролей |
| `departments` | Справочник отделов/локаций |
| `incident_categories` | Справочник типов инцидентов |
| `investigation_comments` | Комментарии к расследованиям |
| `correlation_alerts` | Групповые алерты |
| `correlation_alert_incidents` | Связь alert ↔ incidents |
| `logs` | Журнал аудита |

**Backend:** Node.js, Express, PostgreSQL (pg), JWT (jsonwebtoken), bcryptjs, express-rate-limit, Swagger, Helmet, multer, csv-parse

## Установка и запуск

### 1. Клонировать репозиторий

```
git clone https://github.com/Kenpach1Zaracki/sem4-lab4.git
cd sem4-lab4
```

### 2. Настроить переменные окружения

Создать `backend/.env`:

```
JWT_SECRET=your_secret_key
DATABASE_URL=postgresql://...
EMAILJS_PUBLIC_KEY=...
EMAILJS_SERVICE_ID=...
EMAILJS_TEMPLATE_2FA=...
```

### 3. Установить зависимости и запустить бэкенд

```
cd backend
npm install
npm start
```

### 4. Установить зависимости и запустить фронтенд

```
cd frontend
npm install
npm start
```

Приложение будет доступно:

- Frontend: [http://localhost:3000](http://localhost:3000)
- Backend: [http://localhost:5000](http://localhost:5000)
- Swagger: [http://localhost:5000/api-docs](http://localhost:5000/api-docs)
